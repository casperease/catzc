# ADR-REPO-AI: the agent contract

Every agent and every skill reads this first, at every start and after every clear. One line to act on per rule, then the why.

## Rules: ADR-REPO-AI

### Rule ADR-REPO-AI-READCONTRACTFIRST

**Read this contract first, every start.** Then the DRS index and only the rules your brief cites, by code.
(ADR-REPO-LINK-ONECITATIONSPELLING)

### Rule ADR-REPO-AI-TRUSTTHETREE

**Trust the tree; verify cheaply.** A fact is checked by a read, a grep or a listing, never by a tool run. The committed tree at one commit
is the truth; the working tree is the proposal for the next commit.

### Rule ADR-REPO-AI-TESTSATTHEEND

**Tests cost; postpone them to the end.** Run no test or gate while working; list the checks owed and report them as a warning.

### Rule ADR-REPO-AI-SMALLTESTSDIRECTLY

**A small test may run directly.** One Pester file or one gate on one file, in the background; Test-Automation is the user's. A new tool
counts as working only after one live run of it; green tests alone never vouch for it.

### Rule ADR-REPO-AI-NEVERMUTATEGIT

**Never mutate git.** No add, commit, mv, rm, reset, checkout, stash, rebase; the user commits. Query git only when a read cannot.

### Rule ADR-REPO-AI-WORKFORWARD

**Working forward is safe.** Downstream is quality-controlled; do not re-verify what a gate will verify. (ADR-AUTO-TEST)

### Rule ADR-REPO-AI-SHORTFOREGROUNDCALLS

**Foreground shell calls take at most 3 seconds.** Longer work runs in the background with a timeout prefix.
(ADR-AUTO-FAILFAST-BOUNDEVERYWAIT)

### Rule ADR-REPO-AI-ONEFILEATATIME

**One file at a time; read it back.** No script sweeps, no batch replace. (PDR-ONELIVE)

### Rule ADR-REPO-AI-EDITONLYBRIEF

**Edit only what the brief names.** A shared file gets an entry request; a peer's dirty file is left alone. (ADR-REPO-AGENTS-STANDARDDRONE)

### Rule ADR-REPO-AI-NEVERDECIDEFORUSER

**Questions go to the orchestrator, never straight to the user.** A drone never stops to ask the user: it sends its question to the
orchestrator with its recommendation, labelled as one, and works on meanwhile. The orchestrator decides what the user has delegated,
recorded as delegated in the owning plan, and asks the user the rest in one halt of at most five questions, its recommendation first. An
open question nobody may decide stays open and is reported.

### Rule ADR-REPO-AI-FIXEDREPORT

**End with the fixed report.** Files touched; checks owed and not run; checks run with output verbatim; what was left undone.

### Rule ADR-REPO-AI-DOMAINWORDS

**Use the domain's words.** Domain rules, never "house rules"; cats the product, catzc the inner namespace. (PDR-CATS)

### Rule ADR-REPO-AI-OUTISOUTPUT

**out/ is output; render nothing unasked.** A run reads back only its own stamped folder there, and waits through its absence, since out/
can be wiped at any time. Plans live in .claude/plans; no diagram without an ask. (ADR-REPO-OUTDIR)

### Rule ADR-REPO-AI-EDITORISFACT

**In listen mode the editor's edit is fact.** A doc correction outranks the tree; the repository at the pinned commit is what disagrees. A
fact-check verdict on a note never stands alone: it is written with its reason and the path:line it rests on. For the session, the edit is
the source of truth.

## Context

Agents start cold on small models. Test runs are the largest cost of a session, and a mutating git command by an agent cannot be undone by
the user. The time safeguard bounds every call; this contract bounds what a call is spent on.

A robot's front matter is a closed key set (ADR-REPO-AGENTS-ROBOTBODYLIMIT), and a value identical on every file is a constant, declared
once (PDR-CONFIG, PDR-REDUCEVAR). So the contract every robot and capability reads first is not a per-file key: it is named in the
`contracts` entry of agents.yml, which Test-AgentDefinitions reads, and in the CLAUDE.md session-start line.

In every mode but one, the truth is the whole repository at one commit, committed files only. The listen mode is the exception: the user, as
the editor, isolates a source tree and corrects docs by hand while the listener notes each change. Those corrections are not questions or
proposals; they are the truth the repository is then brought into line with, so the processor that reads the notes plans revisions and never
asks whether the editor is right. It reads the repository only as the reference snapshot at the commit the session pinned.

## Decision

One short contract, named once: the top-level `contracts: [ADR-REPO-AI]` entry in agents.yml, which `Test-AgentDefinitions` reads, and the
CLAUDE.md session-start line. No per-file key. It says what to do and names the ADR that owns the why; under 100 lines with its head.

## Consequences

- A session's cost is bounded by reads, not runs; tests are reported as owed and run by the user.
- A fresh agent on the smallest model follows the contract without the corpus.
- Test-AgentDefinitions reads the required contracts from agents.yml; a front-matter key is not where a contract is named.
