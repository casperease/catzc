# ADR: Generated READMEs — one authored source, copied out per conventional folder with its links rebased

## Rules: ADR-REPO-README

### Rule ADR-REPO-README-GENERATEDCOPY

A `README.md` in a mapped conventional folder is a **generated copy** of an authored docs source, never hand-kept: the source is the one
authored file, and the README is rewritten from it, so the two cannot drift.

- [Decision](#decision)

### Rule ADR-REPO-README-GITIGNORED

Generated READMEs are derived artifacts, gitignored globally (`**/README.md`) exactly like the generated `.psd1` manifests — regenerated on
import, never committed. History and the authored text live elsewhere (git; the source).

- [Derived, not committed](#derived-not-committed)

### Rule ADR-REPO-README-OPTOUT

A folder keeps a hand-authored, committed README by opting out: omit it from the map and un-ignore it in `.gitignore` (`!path/README.md`). A
folder is therefore either generated (mapped, ignored) or committed (unmapped, opted-in) — never both.

- [Explicit opt-out](#explicit-opt-out)

### Rule ADR-REPO-README-ONEMAP

The map from a target folder to its source lives only in `pwsh/Base.Docs/configs/readme.yml` — a glob `patterns` list whose matched folders
derive their source by convention, plus explicit `mappings` for the exceptions — validated by the `DocsConfig` type and expanded by
`Get-ReadmeMappings`; `Build-Readme` is the single writer. The mapping is not restated anywhere else.

- [Decision](#decision)

### Rule ADR-REPO-README-READMEIDEMPOTENT

Generation is idempotent and runs on every import (the importer tail): `Build-Readme` composes each README (`Get-ReadmeContent`) and writes
it through `Write-FileIfChanged`, which rewrites only a README whose content differs (line endings ignored) and writes by delete-then-write,
so a README that is a filesystem link is severed, never written through into its source. A clean tree is a fast no-op.

- [Always current](#always-current)

### Rule ADR-REPO-README-WORKINGLINKS

Every link in a generated README works where the README is opened. Each relative link target is resolved at the source's folder and
rewritten relative to the README's folder (`MarkdownLinkRebaser`); code spans, fenced blocks, URLs, in-file `#anchors`, and
repository-rooted `/` targets are left as written. A line under the title links back to the source as the one place to edit. The source's
front matter, its meta block ([ADR-REPO-FILEMETA-HEADPOLICY](file-meta.md#rule-adr-repo-filemeta-headpolicy)) included, is left out of the
copy. The copy opens with a meta block of its own, `role: readme`, the role the file-kinds registry names for it, and then its title.

- [Readable where it is opened](#readable-where-it-is-opened)

### Rule ADR-REPO-README-AUTHOREDSOURCES

Authored sources live under `docs/references/` — pwsh modules as the responsibilities-first reference articles in
`docs/references/pwsh/<kebab>.md`, and other folders (pipelines, infrastructure, `out/`, `.cspell/`, `contracts/`) under `docs/references/`.
The one mapping outside it is `docs/drs/`, whose README is generated from the folder's own generated index, `docs/drs/index.md`. That index,
the generated glossary, and the per-unit contract pages (`docs/references/contracts/<unit>.md`) are committed, unlike the READMEs — every
rule citation links the index, so GitHub must have it — and marked `linguist-generated` so their diffs collapse. The source is the reviewed
artifact the quality gates check; the README is outside the markdown quality gate's scope.

- [Derived, not committed](#derived-not-committed)

## Context

A `README.md` is what a reader sees first in a folder in an editor. Kept by hand, each drifts from the documentation it duplicates, and the
same content is maintained in two places. The repository treats other per-folder, convention-derived files as generated, gitignored
artifacts, such as each module's manifest. A README is the same shape: one authored source under `docs/`, one derived artifact per folder,
regenerated from the source so it cannot drift.

The artifact is read in the folder it documents. An editor opens `pwsh/<Module>/README.md` and resolves its relative links from that folder,
while the source article authors them relative to its own folder under `docs/references/`. A README that is the source file itself — a
filesystem link — therefore sends every relative link to the wrong place; the README has to carry its own link base.

## Decision

Each mapped conventional folder's `README.md` is generated by `Build-Readme` (module `Catzc.Base.Docs`) from its single source under `docs/`
(`docs/references/`, or the DRS index for `docs/drs/`), declared in `configs/readme.yml` (glob `patterns` + explicit `mappings`) and
validated by `DocsConfig`. The README is the source's text with its relative links rebased to the README's folder, under a line naming the
source. There is one authored copy of the content (the source) and one generated copy per folder (the README).

### Derived, not committed

The README is an artifact, not source. It is gitignored globally (`**/README.md`), the way the generated `.psd1` manifests are
([dedicated-output-directory](dedicated-output-directory.md) treats generated artifacts as out of the committed source set), and it is
excluded from the markdown quality gate — the authored source under `docs/references/` is the reviewed artifact. A quality gate
(`Test-GeneratedReadmes`) holds the three properties together: every generated README is ignored, untracked, and current with its source.

### Explicit opt-out

`Opt-out is explicit and located`

Some READMEs are genuinely authored in place — a GitHub profile landing page, a third-party README, a fixture. Such a folder is simply not
mapped, and its README is un-ignored in `.gitignore` with a `!path/README.md` line. The two expressions stay consistent by construction: a
mapped folder's README is ignored and unmapped-opted-in READMEs are committed, and an integrity test asserts no mapped target is opted back
in.

### Always current

`Always current, at no steady-state cost`

Because the READMEs are cheap to compose and must never go stale, the importer regenerates them on every load. This is safe only because the
write is idempotent: `Write-FileIfChanged` compares the composed content with what is on disk, line endings ignored, and writes nothing when
they agree. A source edited mid-session is picked up at the next import, the same contract as every other generated artifact
([caching](../automation/caching.md)). The write is delete-then-write, so a README left as a filesystem link to its source is replaced by an
independent file and the source is never written through.

### Readable where it is opened

`The README carries its own link base`

An authored article links to its neighbours — sibling references, decision records — relative to its own location, and those links are
checked by the markdown quality gate at that location. The README places the same article in another folder, so `MarkdownLinkRebaser`
resolves each relative target at the source's folder and writes it relative to the README's folder: the link that reads `../../adr/...` in
`docs/references/pwsh/` reads `../../docs/adr/...` in `pwsh/<Module>/`. What is not a relative file reference is left as written — code
spans and fenced blocks (literal text), URLs, in-file `#anchors` (the README has the same headings), and repository-rooted `/` targets (they
resolve the same from anywhere). The rebaser uses the link grammar of the links quality gate (`Test-Links`), so it rewrites exactly the
links `Test-Links` checks.

The line under the title — "Generated from [source] — edit the source; this copy is rewritten on every import" — makes the copy honest: a
reader can follow every link from the README, and a writer is sent to the one file whose edits last.

## Consequences

- Per-folder README content is authored once, under `docs/references/`, and cannot drift — the README is regenerated from it.
- Every relative link in a README resolves from the README's folder, in an editor's link-follow and preview alike.
- An edit made in a README is overwritten at the next import; the banner says so and links to the source.
- Adding a generated README is one mapping line plus its source file; opting a folder out is one `.gitignore` line and leaving it unmapped.
- A source edited mid-session leaves its README stale until the next import, and `Test-GeneratedReadmes` reports it until then.
