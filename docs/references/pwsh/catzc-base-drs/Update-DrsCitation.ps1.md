# pwsh/Catzc.Base.Drs/Update-DrsCitation.ps1

The comments of the file that outgrew one line, one section per comment, verbatim. A section names the code line its comment sat above
(Export-Comments), and Build-CommentView puts every comment back there for reading.

## help

### synopsis

Rewrites the ADR citations, codes, anchors, links, and paths in one file through a code map and a rule map.

### description

The mechanism for moving, renaming, or splitting ADRs: the maps say what moved, and this command rewrites one file's references to match. It
reads the file, rewrites every mapped reference with `[Catzc.Base.Drs.DrsCitationRewriter]`, writes the file only when something changed,
and returns one `[Catzc.Base.Drs.DrsCitationChange]` per reference, with its kind, line, old text, and new text.

It rewrites:

- rule codes, which are named (`ADR-<DOMAIN>-<ADR>-<NAME>`, `TDR-<ADR>-<NAME>`), through the rule map first (a rule that moves or collapses)
  and the code map otherwise;
- every other code of a registered kind (the kinds of drs.yml), through the code map; a new code may be a bare kind, as the code of a domain
  that owns its record kind becomes that kind;
- rule anchors `rule-<code>`, standalone and inside links;
- link destinations into docs/drs/: one with a rule anchor follows the rule, possibly to another file, and any other follows the file. A
  relative link is resolved at the file's folder and written back relative to it; a repository-rooted code link stays rooted
  ([ADR-REPO-LINK-MARKDOWNRELATIVE](../../../drs/repository/markdown-links.md#rule-adr-repo-link-markdownrelative));
- plain path mentions of a mapped ADR file or folder: `docs/drs/<path>`, `/docs/drs/<path>`, a relative path, or a path relative to
  docs/drs/.

Matching is exact, with a token boundary on both sides, and runs through the whole file, fenced code blocks included. A numbered citation
(`<code>:<n>`, `<code>#<n>`), which names no rule since rules are named, is left as written and returned as an Unhandled change, with a
warning message, for a person to resolve. A file with nothing to change is not written, so its bytes stay identical; a changed file keeps
its byte order mark and line endings. Running the command twice is a no-op
([ADR-AUTO-IDEM](../../../drs/automation/idempotent-state-functions.md)).

The maps are the tab-separated files a migration plan produces: the code map (old_code, new_code, old_path, new_path, kind; paths relative
to docs/drs/; '-' for none; kind move, path, new, folder, or root, where a folder row maps its file's folder too, and the one root row, its
two paths repository-relative, moves the root itself to a folder of the same depth, so every path under it moves, a bare mention of the root
moves with it, and a relative link is written from the citing file's place after the move) and the rule map (old_rule, new_rule, kind, why;
each rule a named rule code; kind move or collapse). The path of a rule's new code comes from the code map, else from the ADR index
(Get-DrsCitationMap). Code links are regenerated by Format-Links afterwards; this command already writes them consistently, so the file is
whole after one call.

### parameter `Path`

The one file to rewrite: absolute, or relative to the repository root. It must be inside the repository root.

### parameter `CodeMap`

The code map file (absolute, repository-relative, or under out/).

### parameter `RuleMap`

The rule map file (absolute, repository-relative, or under out/).

### parameter `RepositoryRoot`

The repository whose ADR index supplies the paths the code map does not name, and against which -Path and relative links resolve. Defaults
to the loaded repository root.

### parameter `DryRun`

Return the changes without writing the file. See [ADR-AUTO-DRYRUN](../../../drs/automation/dry-run.md).

### outputs

`[Catzc.Base.Drs.DrsCitationChange]` One per rewritten (or Unhandled) reference, in file order.

### example 1

```powershell
Update-DrsCitation 'docs/index.md' -CodeMap 'out/split/code-map.tsv' -RuleMap 'out/split/rule-moves.tsv' -DryRun
Lists what would change in docs/index.md without writing it.
```

### example 2

```powershell
git ls-files '*.md' '*.ps1' '*.cs' '*.yml' | ForEach-Object { Update-DrsCitation $_ -CodeMap 'out/split/code-map.tsv' -RuleMap 'out/split/rule-moves.tsv' -DryRun } | Group-Object Path
Lists, file by file, what would change across the tracked text files without writing any. -Path takes one file, so a tree-wide dry run is one pipeline that calls the command per file; each call reads both maps and the ADR index again, and a file that is not valid UTF-8, such as a binary, throws, so the list names text files only.
```
