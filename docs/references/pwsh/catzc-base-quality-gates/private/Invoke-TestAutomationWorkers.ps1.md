## help

### synopsis

Runs the test files through the parallel worker pool (and the serial phase) and aggregates the rows.

### description

Test-Automation's execution engine. Runs in the location its test run claimed (Enter-TestRunLocation — a run never waits for another: it
runs in place when the working folder is free, and in a verified snapshot of it when another run holds it;
[ADR-AUTO-TEST-RUNSNEVERWAIT](../../../../drs/automation/test-automation.md#rule-adr-auto-test-runsneverwait)), round-robins the parallel
files across worker shards (generated by New-TestAutomationShardScript) and runs them through the PesterRunner pool — live pooled output, at
most one shard per worker. The greedy phase shares that pool: each greedy-tagged file becomes its own single-file shard, queued behind the
parallel shards, and takes the first slot a shard frees, so the pool never runs more workers than the parallel phase. At most
greedy_group_size greedy files run at once (test-policy.yml, default 2; -GreedyGroupSize overrides it), and of the files greedy_apart names
(the ones that run real builds) one at a time
([ADR-AUTO-TEST-ONESCHEDULINGPOOL](../../../../drs/automation/test-automation.md#rule-adr-auto-test-oneschedulingpool)). Finally the
serial-tagged files run in a one-worker phase, alone. Aggregates every shard's `rows-shard-<N>.json` sidecar in shard order; a worker that
exited outside {0,1} or never wrote its sidecar crashed before finishing, and the aggregation throws naming the shard rather than reporting
a partial run as the whole truth.

In a snapshot run the test files map to the same repository-relative paths inside the snapshot, each worker loads the snapshot's own
importer (or the test run's entry script with its repository root mapped to the snapshot), and the run directory stays in the working
folder's out/ — the shard results land home by construction, and the rows' File paths map back to working-folder paths before aggregation.

### parameter `ParallelFiles`

The test files to shard across the pool (may be empty when only tagged files are in scope).

### parameter `GreedyFiles`

The greedy-tagged test files — one single-file shard each, queued behind the parallel shards in the same pool (may be empty).

### parameter `SerialFiles`

The serial-tagged test files for the final one-worker phase (may be empty).

### parameter `Location`

The location the test run claimed (Enter-TestRunLocation) — where the run executes. The caller releases it.

### parameter `RunDirectory`

The run directory the shard scripts and their artifacts are written into.

### parameter `ExcludeTag`

Tags excluded from every worker's run (from Get-TestExcludeTag).

### parameter `IncludeTag`

Tags every worker's run is limited to; empty runs every test the other filters keep.

### parameter `Verbosity`

Pester output verbosity inside each worker.

### parameter `Workers`

Explicit pool size; 0 sizes automatically — max(1, ProcessorCount / 4), never more than the file count.

### parameter `GreedyGroupSize`

At most this many greedy files run at once in the pool; 0 reads greedy_group_size from test-policy.yml.

### parameter `TimeoutSeconds`

Hard ceiling per execution phase; on expiry the pool is killed and the run throws. The entry point's own limit, passed down by
Invoke-TestRun, with no default here.

### parameter `WorkerEnvironment`

Extra environment variables for each worker's process (the L0/L1 tripwire) — never the parent's $env:.

### parameter `EntryScript`

The run seam passed to every shard script (New-TestAutomationShardScript): empty loads the source importer; the build run passes the build's
Import-Catzc.ps1.

### parameter `EntryParameter`

Named arguments for -EntryScript (the build run's @{ RepositoryRoot = `<repo>` }).

### outputs

`[pscustomobject]` with Rows (aggregated, in shard order), Files (every shard's files-sidecar entries — File as a working-folder path,
DurationMs, Result, ErrorMessage), FailedShardLabels (shards that exited 1), ShardExitCodes (label -> exit code, for the run manifest),
Shards (the shard descriptors, serial last), WorkerSummaries (one per worker: queue number, label, file/test tallies, wall-clock start and
duration — the end-of-run table's rows), DurationSeconds (wall clock across both phases), and Location (the -Location the workers executed
in, the same object — Get-TestRunLocationSummary renders it for the run manifest and the report).
