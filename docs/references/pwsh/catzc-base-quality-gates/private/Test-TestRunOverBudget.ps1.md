## help

### synopsis

Whether a test run outlasted its whole-run budget in a way that fails it: a devbox run over tests.run_seconds.

### description

The whole-run budget fails a devbox run that outlasts it
([ADR-AUTO-TEST-DEVBOXRUNBUDGET](../../../../drs/automation/test-automation.md#rule-adr-auto-test-devboxrunbudget)) — the time safeguard's
fail-fast stance applied to the run itself
([ADR-AUTO-FAILFAST-BOUNDEVERYWAIT](../../../../drs/automation/fail-fast-with-asserts.md#rule-adr-auto-failfast-boundeverywait)): a slow run
is a defect to fix, not a wait to absorb, and the budget is a roof that is never raised to make a run pass. A pipeline run is bounded by its
stage's own limit instead, so it never fails here. A failing run says so on the console, with its time and the budget.

### parameter `DurationSeconds`

The run's wall clock — its workers' run, as the run reports it.

### parameter `BudgetSeconds`

The whole-run budget (Get-TestTimeLimits RunSeconds, tests.run_seconds in timeouts.yml).

### outputs

`[bool]` True when the run fails on its budget.

### example 1

```powershell
Test-TestRunOverBudget -DurationSeconds 201.3 -BudgetSeconds 180
```
