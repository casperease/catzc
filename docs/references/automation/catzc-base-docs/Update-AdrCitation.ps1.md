# automation/Catzc.Base.Docs/Update-AdrCitation.ps1

The comments of the file that outgrew one line, one section per comment, verbatim. The file keeps one line and a link per section
(Export-Comments), and Build-CommentView puts them back for reading.

## comment:1

Section `.DESCRIPTION` of the comment-based help.

```text
The mechanism for moving, renaming, or splitting ADRs: the maps say what moved, and this command rewrites one
file's references to match. It reads the file, rewrites every mapped reference with
[Catzc.Base.Docs.AdrCitationRewriter], writes the file only when something changed, and returns one
[Catzc.Base.Docs.AdrCitationChange] per reference, with its kind, line, old text, and new text.

It rewrites:
  - rule citations ADR-<CODE>#<n> and the heading form ADR-<CODE>:<n>, through the rule map first (a rule that
    moves or collapses) and the code map otherwise; in a list (ADR-<CODE>#1, #5 and #7) each inherited #<n>
    follows its own rule and takes its new code when that differs from the one before it;
  - bare codes ADR-<CODE>, through the code map;
  - rule anchors rule-<code><n>, standalone and inside links;
  - link destinations into docs/adr/: one with a rule anchor follows the rule, possibly to another file, and any
    other follows the file. A relative link is resolved at the file's folder and written back relative to it; a
    repository-rooted code link stays rooted
    ([ADR-REPO-LINK#2](/docs/adr/repository/markdown-links.md#rule-adr-repo-link2));
  - plain path mentions of a mapped ADR file or folder: docs/adr/<path>, /docs/adr/<path>, a relative path, or
    a path relative to docs/adr/.

Matching is exact, with a token boundary on both sides, and runs through the whole file, fenced code blocks
included. A citation range (ADR-<CODE>#1 to #6) that spans a moved rule is left as written and returned as an
Unhandled change, with a warning message, for a person to resolve. A file with nothing to change is not written, so its
bytes stay identical; a changed file keeps its byte order mark and line endings. Running the command twice is a
no-op ([ADR-AUTO-IDEM](/docs/adr/automation/idempotent-state-functions.md)).

The maps are the tab-separated files a migration plan produces: the code map
(old_code, new_code, old_path, new_path, kind; paths relative to docs/adr/; '-' for none; kind move, path, new,
or folder, where a folder row maps its file's folder too) and the rule map (old_rule, new_rule, kind, why; rules
spelled ADR-<CODE>:<n>; kind move or collapse). The path of a rule's new code comes from the code map, else
from the ADR index (Get-AdrCitationMap). Code links are regenerated by Format-Links afterwards; this command
already writes them consistently, so the file is whole after one call.
```
