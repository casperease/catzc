# How one setting travels from a default declared once to the value a call uses

## Sections

- varying-is-config: One setting followed from the principle that makes it configuration, through its one resolution order, into the
  code and the gates that hold it, and up to the records that check the deck itself.

## About

The deck is the visual of the configuration principle, [configure-not-program](../../../drs/principles/configure-not-program.md), and
the one resolution order of a setting in [sensible-defaults](../../../drs/automation/sensible-defaults.md): a behaviour that varies is a
config entry with a default declared once, and every consumer reads it in the same order. The slides follow one setting down into a
module, a contract and a time limit, then across to the robots and the diagrams that are configured the same way, and end on the record
that verifies the deck. Every slide is one fact with the code of the record it rests on, and shows one diagram of the catalogue, reduced,
from the same seeded pool as the sister deck [truth-travels](../truth-travels/deck.md).
