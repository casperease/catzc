# Minimap inputs only: a diagram's declaration holds what its minimaps are computed from, never the computed cells

Every diagram declaration (9 `*.drawio.yml` files and 168 Markdown files with a `yml drawio` block) carries, under `content.minimaps`, every
lit cell of every shown minimap with the files and rule codes that lit it (`{ cell, by: [...] }`), written back by `declaration.py minimaps`
from what the minimap data commands compute. The only input is the declaration's own `about.adrs`: the cells and `by` lists are the files
that cite those codes, projected onto each minimap's axes. So the declaration stores derived data that goes stale whenever a citing file
moves or is added, churns on edits nobody made to the diagram, and runs to dozens of lines per diagram.

## Why its value

A declaration that stores only its input is short, never stale, and changes only when its author changes it (PDR-ONELIVE: one source, the
citations in the tree; the copy in the declaration is a second one). It removes the bulk of every diagram block in the docs.

## Decided (the user, 2026-10-23)

- A declaration saves only the inputs of its minimaps, never their data, for every minimap id (`code-locations`, `module-neighbourhood`,
  `axis` and the rest of the eight). This reverses the 2026-10-21 decision that the placed cells with their `by` lists live in the
  declaration.
- The input is `about.adrs`, plus which minimaps are shown; the cells and their reasons are computed at build time from the tree, as the
  minimap data commands already do, and kept in `out/minimaps/` only.
- Nothing stored replaces the review the listed cells gave; a minimap may take an optional `exclude:` input, the cells its author rejects,
  so the declaration still holds inputs only.
- The rendered png stays committed, re-rendered by `Build-Diagrams -Stale`, with `Test-Diagrams` naming the stale ones.
