# task007: body-sha Phase 0, the hash only on generated tracked files

Decided (Q10, go now): a body hash is required and autogenerated on generated, git-tracked files; an authored page never needs one, a
hand-added one is no finding and is never maintained. Today `file-meta.yml` kind `body-sha` selects `{ languages: [markdown] }` (line 24),
so every authored page is stamped and every ADR edit is a drift finding until Format-FileMeta runs. This change makes every later edit
cheaper and unblocks the ADR link cleanup (T027). C# edits need a fresh pwsh; the gates run in the background under the time safeguard.

## Steps

1. `git status --short automation/Catzc.Base.QualityGates/configs/file-meta.yml`; if dirty, stop and report (a peer holds it). Check: clean.
2. `file-meta.yml` kind `body-sha`: the selector becomes the generated class. Read how other kinds select by class in the same file (the
   `repo-status` kind uses `settings.locked_classes: [comment-page]`; class selectors are `{ classes: [...] }` if present, else the kinds
   the `.gitattributes` `linguist-generated` patterns mark). Write `select: [{ classes: [generated] }]` or the equivalent the config type
   accepts; if no `generated` class exists yet, define it in the same file from the `.gitattributes` generated patterns (one source: cite
   the `generated-head.yml` kinds). Check: `FileMetaConfig` type tests pass; `Test-FileMetaProcessors` counts unchanged (17 kinds, 18
   processors).
3. `Get-BodyShaFileMetaFact.ps1`: a file outside the generated class returns no fact and reports nothing, present or absent (a hand-added
   `with_body_sha` is left alone). Its test gains two cases: authored page with a hash is no finding; authored page without one is no
   finding. Check: `Get-BodyShaFileMetaFact.Tests.ps1` passes.
4. `Format-GeneratedFileHead.ps1`: the generated head gains `with_body_sha` (hash of everything below the head) beside `with_inputs_sha`;
   the key order follows ADR-REPO-FILEMETA#7. Its test checks the key and that the hash changes when the body does. Check: its Pester file.
5. `Test-GeneratedFiles.ps1`: drift compares head hash to body hash for every generated tracked file; the 264 diagram grid, tree and chain
   text files and the 2 `automation/.compiled` files (the json manifest and whatever else is tracked there) must carry a head, which their
   generators write through the one head function. One generator per step if several need the change. Check: `Test-GeneratedFiles` clean
   after the generators run (background).
6. One `Format-FileMeta` run over the tree (background, 360 s cap) removes `with_body_sha` from authored pages; read the diff stat. Check:
   `Test-FileMeta` clean; `git diff --stat` shows only head lines removed.
7. `docs/adr/repository/file-meta.md`: rule 3 says body_sha is required and autogenerated on generated tracked files only; rule 7 lists it
   among the generated head's keys; both in present tense, no "now" or "no longer". Check: Test-AdrRegistry, Test-Links, Test-Markdownlint
   clean on the file.
8. `plan-plans-body-sha-landing-zone.md`: tick the Phase 0 step with the Test-FileMeta verdict. `plan-adr-link-cleanup-prose-to-pages.md`
   head: `blocked_on` drops "phase 0". Check: grep "phase 0" in that head finds nothing.
