# Every generated artifact known, stamped and rollable

## Why high

Generated output is the repository's weak spot. Of 130 MB tracked, 100 MB is PNG, and most of it is not known as generated: 201
`*.drawio.png`, 185 `*.slide.png` and 91 slide pictures (`<id>.png`) come from a chain (a `.drawio.yml` or a `yml drawio` block in an
article, then the png, then the picture, then the slide png) that only `Build-Diagrams` half declares, as a target with no inputs. The
`generated` fact is spread over six configs (`generated-files.yml`, every module's `configs/generated.yml`, `rootconfig.yml`, `readme.yml`,
`comment-pages.yml`, the variants members' `generated`/`committed`), which is two answers to one question (PDR-ONELIVE). Nobody can safely
take the generated files out of a working copy and render them back, and a reader of a png cannot learn where it comes from.

## Decided

- The registry is the one truth: each module's `configs/generated.yml` declares its writers whole (name, inputs, outputs, class, check, and
  for each output the inputs it reads); `pwsh/Base.GeneratedFiles/configs/generated-files.yml` is deleted. `readme.yml`, `rootconfig.yml`
  and `comment-pages.yml` stay as the configs that expand a writer's instances; its row points at them.
- Re-render order is derived from the input/output graph, never listed by hand. The same graph answers "what is this file's source" and "is
  it stale" (the writer's input-hash stamp), images included.
- A writer has one class: `rollable`, `import-critical` (importer, root configs, track-sets, module manifests: never rolled off, since the
  session that restores them must import), `snapshot` (reads outside the tree, `Update-AzurePriceTable`, `Update-AdoFlowOccupants`: never
  rolled off), `untracked` (out/, bin/obj, .venv).
- Roll off / roll on is one operation over the existing `generated` filter view (`filters.yml`): `Remove-Generated` deletes the view's
  rollable files from the working copy, so git shows them deleted; `Restore-Generated` runs their writers in graph order. A clean round trip
  (`Remove-Generated`, `Restore-Generated`, then `git status` shows no change) is the safety proof.
- The head is a stamp, never a source: every committed generated file carries one, projected from its registry row when the writer writes it
  and never read back (ADR-REPO-FILEMETA-NOREADBACK). It is a one-way note to a person and may be out of sync, so no command decides
  anything from it: which files are generated, which `Remove-Generated` deletes and which `Restore-Generated` renders come from the registry
  alone, and a file with a head on no declared path is authored as far as every tool is concerned. `with_body_sha` stays only as the drift
  check's fast path, which falls back to the full render on any mismatch. Keys, in order: `warning`, `regenerate`, `with_body_sha`; no
  `sources` and no `remove`, which the registry answers. The `regenerate` command is a template declared once in `generated-head.yml`
  (`"{writer} -Path {path}"`), a writer row overriding where its call differs; no writer words its own head.
- One head renderer: the C# type renders the head text; PowerShell and Python writers both stamp through it, Python by calling the one
  command, never by a copy of the logic.
- A carrier for every committed generated format: png a `tEXt` chunk keyed `catzc` (the body sha hashes the image without it), svg a
  `<metadata>` element, xml a `<?catzc ...?>` processing instruction, json the `"//"` property. A generated format with no carrier is never
  committed.
- This reverses ADR-REPO-FILEMETA-PROVENANCEINHEAD's "the registry answers, never written into the file" and widens
  ADR-REPO-FILEMETA-COMPOSEDFILES's two-key head; both rules are reworded in the same change as the head type, and the 2026-10-19
  body-sha-only decision is superseded.
- Authored: the 76 `js/track-lamps/assets/*.svg`. They are the base glyphs `New-VsCodeExtensionFolder` copies into the built extension's
  `media/` under the output root and recolours there with the lamp palette; no writer in `js/` or `pwsh/` writes into the assets folder.
- Generated by `flow_glyphs.py`: the six `python/diagrams/assets/flow/*.svg`. `write_all()` renders each `drawio.yml` `flow-glyphs` entry
  into `ASSETS`, and a fresh render matches all six byte for byte. They get a writer row in the unregistered-writers step.
- Comment pages are authored (ADR-REPO-COMMENTS-PAGEISAUTHORED), so `Get-GeneratedTarget` declares no comment-page root.
- A frozen contract asset carries no head (ADR-REPO-CONTRACT-RELEASEDIMMUTABLE). A release folder's bytes are fixed by its `.frozen` record,
  and no writer re-renders them, so `Publish-ContractRelease` strips the stamp when it copies `0.1.0`. The `0.1.0` `types.json`
  (`Write-TypesContract`) is never frozen, so it carries the json `"//"` head. The stamp-head step widens `types.schema.json` (root
  `additionalProperties: false`) and `Get-TypesContractDrift` to skip `"//"`.

## Open steps

### Roll off, roll on

- [x] A `check: gate` writer is proven fresh, not only named: `Test-GeneratedFiles` flags a gate-checked output older than its inputs (63
      committed `*.slide.png` were stale against their pictures and no gate saw it). Check: its Pester test with a stale fixture output.
- [x] The minimap reads only HEAD: `Get-WorldMap`'s configs, tracks, aspects, DRS rule sets and globsets, and `Get-MinimapFact`, read the
      commit, not the working copy. `Build-Diagrams` discovery (`Get-GitChangedPath`) stays on the working copy, since it is not a minimap
      input and it lets a new diagram get its first put. Check: a working-copy edit leaves a `Build-Diagrams -Path` render byte-equal in a
      fixture test.
- [x] `stamp.py` passes one `-Path` array per writer, so a batched stamp stays under the 32,767-character command line at any slide count.
      Check: its python test with 400 paths makes one call under the limit.
- [x] `Write-TypesContract` is rewritten by every import: its class is `import-critical`, not `rollable`. Check: `Test-GeneratedFiles` 0
      issues and `Restore-Generated.Tests.ps1` passes.
- [x] `Get-GeneratedTrackedPath` claims a path by the most literal glob (`Get-GeneratedWriterOutputPath`), so `*.slide.png` belongs to
      `slide_png render`. Check: its Pester test with overlapping globs.
- [x] The run-lock tests remove their own `catzc-test-*.holder` records. Check: `Wait-CatzcRunLock.Tests.ps1` passes and leaves no test
      holder in `%TEMP%\catzc-run-queue`.
- [x] The output-claim rule is public: `Get-GeneratedWriterOutputPath` leaves `Base.GeneratedFiles/private/` for a public home both
      `Get-GeneratedTrackedPath` and `Restore-Generated` call, so no module calls another's private function. Check: both test files pass
      and `Test-ModuleDependency` reports 0 issues.
- [x] `Get-GeneratedGateDrift` has its comment page and `test-generated-files.md` describes the gate freshness check. Check: `Test-Spelling`
      and `Test-Links` on both pages report 0 issues.
- [ ] The round trip on the real tree: `Remove-Generated`, `Restore-Generated`, `git status --porcelain` empty. Check: the user's full run.
