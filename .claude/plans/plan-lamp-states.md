# Lamp states: the user's switch, the domain's condition, one icon per pair

Each lamp controls one filter on the Explorer and watches its domain, the files its filter's sets claim. Two independent dimensions decide
its icon. The **switch** is the user's: on (lit, the domain's files in the tree) or off (unlit, filtering them away), kept per workspace.
The **condition** is the domain's: committed, staged, unstaged or failed. The engine looks the icon up in a table of switch × condition;
nothing else lives in the button. The tree is the union of the lit lamps: a file is hidden only while no lit lamp claims it.

## Why its value is high

The lamps are the user's daily view of the repository. With a condition per domain they also say where the work in progress is and which
domain is broken, including domains filtered out of the tree, without opening the Source Control or Problems view. VS Code already holds
both facts live, the git state that colours the Explorer and the diagnostics that mark its files, so the lamps read them and reproduce
nothing.

## Decided (2026-10-24)

- The switch keeps today's feel: one click puts a lamp on or off, and a lamp's on/off never changes any lamp's condition.
- Union: a file shows while at least one lit lamp claims it; putting a lamp out hides only the files no other lit lamp claims.
- Conditions, one precedence: failed > unstaged > staged > committed. A domain with both staged and unstaged work shows unstaged.
- Colours: committed green (`#3fb950` lit, `#1f6f3a` unlit ring), staged dark brown (`#7a4a1e`), unstaged yellowish (`#e0b83a`), failed red
  (`#f85149`, its unlit badge blinking). The icons exist as `<lamp>-<on|off>[-<staged|unstaged|failed>].svg`.
- The Explorer's git decoration colours follow the lamps (staged dark brown, unstaged yellowish), one mapping in the repository.
- Every condition is read from what VS Code already knows, never from pwsh, a spawned git or a file watcher of the lamps' own:
  - brown from the built-in git extension's API (`vscode.git`, `getAPI(1)`): a domain is staged while one of its files is in
    `state.indexChanges`, unstaged while one is in `workingTreeChanges`, `untrackedChanges` or `mergeChanges`; recomputed on the
    repository's `state.onDidChange`. It is the same reader that colours the Explorer, so the lamp and the tree never disagree.
  - red from the diagnostics (`vscode.languages.getDiagnostics`, `onDidChangeDiagnostics`): a domain is failed while one of its files
    carries an Error diagnostic, from any analyzer or compiler VS Code runs. A fixed file drops its diagnostic, so red lapses by itself.
- Each changed or diagnosed path is classified by the filters' sets with the extension's one claimer; no domain identity or SHA is computed
  in the extension. The durable globset SHA stays the pipelines' (FDR-CD-GLOBS-DURABLESHAIDENTITY).
- Test-run failures are not red yet: VS Code exposes no test results to other extensions; they join red when a run reports them as
  diagnostics.
- The manifest's state commands and icons expand from `filters.yml` × the states in the folder generator; a new filter stays one config
  line.
