## Goal

Every CAF landing-zone ADR code becomes a segmented code: the `CAF` family is its own segment (4 blocks), and the three network ADRs form a
`NET` sub-family under it (5 blocks). One living version (`ADR-PRIN-ONELIVE`): the old codes, anchors and terminology tokens are deleted in
the same change, with no aliases.

## Tooling check (done, read-only)

Every validator already accepts 4- and 5-block codes, so **no C# or regex change is needed**:

- `AdrsConfig.ExternalRe` `^ADR-[A-Z]{2,4}(-[A-Z]+)+$` and the effective-code prefix rule (`ADR-AZ-` prefix holds).
- `AdrCitationRewriter`, `CodeLinkRewriter`, `CitationScanner`, `MarkdownLinkScanner`, `GlossaryConcept.CitationRe`, `AgentEntry`,
  `AnalyzerAdrMapConfig`, `Get-CatsAdrRules`, `Get-CatsAdrIndex`, test-tag checks: all `ADR(-[A-Z]+)+` with no segment cap.
- Precedent: `ADR-FLOW-CD-RUNNER` is a live 4-block code with anchor `rule-adr-flow-cd-runner<n>`.

Phase 0 still proves this with one real 5-block code before the sweep (a dry run, not a belief).

## Decisions (agreed: the recommended option in each)

- **D1 — segment grammar (agreed: as in the code map).** `CAF` is a family segment for all CAF ADRs; `NET` is a sub-family only for the
  three network ADRs. Alternative: 4 blocks everywhere (`ADR-AZ-CAF-NETPRV`). The 5-block form is what you asked for "even"; it makes
  `ADR-AZ-CAF-NET-*` greppable as one family, at the cost of two extra chars per citation.
- **D2 — leaf `code:` in `adrs.yml` (agreed: none).** `AdrsConfig.CodeRe` allows at most two segments (`AZ-CAF`), so `AZ-CAF-NET` cannot be
  a leaf code. Leave the domain code `AZ` and let `external:` carry the segments, as `ADR-FLOW-CD-*` does under `code: FLOW-CD`. (Making
  `azure` a compound domain is wrong: the domain also owns `ADR-AZ-DATAMOD` etc.)
- **D3 — WAF in the same change? (agreed: no, a follow-up with the same maps).** `ADR-AZ-WAFRE` → `ADR-AZ-WAF-RE` is the same shape and the
  same mechanism; doing it later keeps this change reviewable.
- **D4 — terminology tokens (agreed: per-segment tokens).** The `caf*` body tokens die with the codes. The spell checker splits on `-`, so
  it needs the segments instead. New terms (only those not already known — `prin`, `mgmt`, `devops`, `waf` exist; `bill`, `name`, `top`,
  `con`, `net`, `sec`, `gov` may pass as English or need entries): `caf`, `iam`, `resorg`, `prv`, plus whichever of the others
  `Test-Terminology` flags. Each ruleset's `terminology:` in `adrs.yml` becomes its last non-English segment (`prv`, `resorg`, `iam`, …) or
  is dropped where the segment is an English word.

## Phases

### Phase 0 — coordinate and freeze (blocker)

Another session is actively editing these exact files right now (`git status`: `AM`/`MM` on `identity-and-access.md`, `network-*.md`,
`platform-automation-and-devops.md`, `adrs.yml`, `terminology.yml`, and all WAF files). Rewriting ~690 references under a concurrent writer
corrupts both changes.

1. Message that session (or wait for its commit) — the CAF authoring wave must land first, including `ADR-AZ-CAFDEVOPS`'s registration in
   `adrs.yml`/`terminology.yml`/`index.md`. If it is not registered by then, register it in Phase 1 directly under its new code.
2. Re-run the reference tally on the clean tree; update the counts above.

Re-checked 2026-10-15 after the decisions: the CAF ADRs, `adrs.yml`, `glossary.yml`, and `docs/references/caf/` are clean, and
`ADR-AZ-CAFDEVOPS` is now registered in `adrs.yml`. Only `terminology.yml` still holds another session's staged change, so check with that
session before Phase 3 step 2 edits it.

### Phase 1 — the maps

Write `out/caf-code-segments/code-map.tsv` (12 rows, `old_path` = `new_path` because only the code changes) and
`out/caf-code-segments/rule-moves.tsv` (header only: no rule moves or renumbering). Use the format `Update-AdrCitation` documents:
`old_code	new_code	old_path	new_path	kind`, with paths relative to `docs/adr/`. The documented kinds are `move`, `path`, `new` and `folder`. A
code-only rename is presumably `move` with identical paths, but check that against `Update-AdrCitation.Tests.ps1` before writing the map.

### Phase 2 — proof on one file (dry run)

`Update-AdrCitation docs/adr/azure/caf/network-private-access.md -CodeMap … -RuleMap … -DryRun`. Check the returned changes cover: the
`## Rules:` heading, every `### Rule …:<n>` heading, `#<n>` citations including inherited lists (`ADR-AZ-CAFNETPRV#1, #5 and #7`), cross-ADR
citations, relative-link anchors, and zero `Unhandled` entries. This is the 5-block canary. Also grep for links to the registry heading's
own anchor (`#rules-adr-az-cafnetprv`). The tool documents rule anchors (`rule-<code><n>`) but not that heading anchor, so any such link may
need a hand edit.

### Phase 3 — registry and index

1. `adrs.yml`: 12 `external:` values and `terminology:` tokens per D4 (Edit tool, one file).
2. `terminology.yml`: delete the 12 `caf*` body entries; add the segment tokens per D4.
3. `Build-AdrIndex` regenerates `docs/adr/index.md`; diff shows only the 12 rows (and table column widths).
4. Check: `Test-AdrRegistry`, the `AdrsConfig` type tests.

### Phase 4 — rewrite citations, one file at a time

Per the domain rules (no batch sweeps), run `Update-AdrCitation` on **one** file, verify it, then the next. Order: the ADR with the most
inbound citations last, so cross-file anchors are checked against already-renamed headings:

`network-private-access.md` (canary, from Phase 2) → `network-connectivity.md` → `network-topology.md` → `design-principles.md` →
`governance.md` → `naming-and-tagging.md` → `management.md` → `resource-organization.md` → `billing-and-tenant.md` →
`platform-automation-and-devops.md` → `identity-and-access.md` → `landing-zone-security.md` → `docs/references/caf/index.md` →
`automation/Catzc.Azure.Templates/configs/glossary.yml`.

Per-file verification:

- `git grep -n -E "ADR-AZ-CAF[A-Z]" -- <file>` returns nothing (no old code left).
- `Test-Links` on the file (anchors resolve, `ADR-REPO-LINK`); `Format-Links` if any code link was touched.
- Line length: every citation grows by 1–2 chars. Re-wrap any paragraph that now exceeds the column limit with `Format-MarkdownParagraph`,
  and let the markdown formatter re-pad any table holding a code (`ADR-REPO-FORMAT`).

### Phase 5 — whole-tree checks

- `git grep -n -i -E "adr-az-caf(prin|bill|iam|resorg|nettop|netcon|netprv|sec|mgmt|gov|name|devops)" -- . ':!out'` → empty (codes, anchors,
  and tokens all gone).
- `Test-AdrRegistry`, `Test-Links`, `Test-Terminology`, `Test-Glossary` (glossary regenerated with `Build-Glossary` if a defining rule's
  citation changed).
- `Update-AdrCitation` re-run over the 14 files returns no changes (idempotent, `ADR-AUTO-IDEM`).
- Per the agreed workflow, the full `Test-Automation` run and the commit stay with you.

## Delegation (optional)

Phases 3 and 4 fit one `catzc-worker` each: Phase 3 owns `adrs.yml`, `terminology.yml`, `index.md`; Phase 4 owns the 14 citing files and
runs them serially (parallel workers would race on cross-file anchors). The coordinator owns the maps.

## Risks

- **Concurrent session** on the same files (Phase 0) — the main risk.
- **`ADR-AZ-CAFDEVOPS` unregistered:** `Update-AdrCitation` resolves a new code's path from the code map first, so it works before
  registration, but `Test-AdrRegistry` and `Test-Links` will flag it until it is in `adrs.yml`.
- **Spell checker on anchors:** `rule-adr-az-caf-net-prv3` tokenises to `prv3`; confirm `Test-Terminology` accepts the digit suffix as it
  does for `rule-adr-flow-cd-runner3`.
- **Stale plans in `out/`** (`plan-caf-waf.md`, `caf-*-verify.ps1`) cite old codes; they are scratch output and are not rewritten unless you
  want them re-cited.
